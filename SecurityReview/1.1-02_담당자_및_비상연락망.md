# 1.1 담당자 및 비상연락망

## 문서 정보
- 기준일/버전: 2026-07-21 / 1.0
- 주의: 저장소와 서버에서 실제 담당자·연락처를 확인할 수 없어 임의 작성하지 않았다. 운영 승인 전 반드시 확정해야 한다.

## 2. 비상 연락 우선순위
1. 서비스 책임자
2. 시스템 운영자
3. 장애 영역 담당자(DB/네트워크/애플리케이션/정보보호)
4. 부 담당자
5. 조직 비상대응 체계 또는 관제센터

## 3. 장애 등급
| 등급 | 기준 | 최초 통보 목표 | 예시 |
|---|---|---|---|
| 심각 | 정보유출 의심, 관리자 탈취, 전체 서비스 중단 | 즉시 | 비밀값 유출, DB 침해, 랜섬웨어 |
| 높음 | 주요 기능 불가 또는 데이터 적재 중단 | 30분 이내 | DB 장애, API 전체 실패 |
| 보통 | 일부 기능 장애, 우회 가능 | 2시간 이내 | 특정 수집기/대시보드 오류 |
| 낮음 | 성능 저하·표시 오류·문의 | 업무시간 내 | 통계 지연, 비핵심 UI 오류 |

## 4. 통보 내용
- 발생 시각과 최초 탐지자
- 영향 서비스·사용자·데이터 범위
- 오류 메시지와 관련 로그 위치
- 현재 프로세스·포트·DB 상태
- 수행한 조치와 결과
- 필요한 승인 또는 지원
- 다음 보고 예정 시각

## 5. 보안사고 시 추가 통보
다음 항목은 서비스 재시작보다 정보보호 담당자 통보와 증거보존을 우선한다.
- 관리자 또는 API 토큰 탈취 의심
- 비정상 RDP·WinRM·DB 접속
- Defender 탐지 또는 악성 PoC 실행 의심
- 개인정보·인증정보 노출
- 로그 삭제·변조 의심

## 6. 정기 검증
- 월 1회 연락처 유효성 확인
- 분기 1회 비상연락 모의훈련
- 인사이동·조직개편 당일 문서 개정
- 실제 연락망은 접근권한이 제한된 사내 문서 저장소에도 동일하게 관리
