# 1.2 테이블 명세서

## 문서 정보
- 기준일/버전: 2026-07-21 / 1.0
- DB: MySQL `TOTORO`, InnoDB, utf8mb4
- 기준 스키마: `migration_package\002`~`015` 및 `web/server.js`
- 주의: 운영 DB의 실제 `information_schema` 대조가 필요하며 본 문서는 배포 SQL 기준이다.

## 1. 핵심 테이블

### Github_CVE_Info
GitHub PoC 원본과 처리상태.

| 컬럼 | 형식/제약 | 설명 |
|---|---|---|
| id | INT PK AI | 식별자 |
| date | TEXT | 저장소 날짜 |
| collect_time | TEXT | 수집시각 |
| link | TEXT | 저장소 URL |
| title/writer/cve | TEXT | 제목·작성자·CVE |
| readme/trans_msg | LONGTEXT | 원문·번역 |
| download_path | TEXT | 로컬 경로 |
| status | TEXT default N | 외부 전달 상태 |
| AI_chk | TEXT default N | AI 분석 상태 |
| cve_info_status | TEXT default N | CVE 상세 수집 상태 |

인덱스: cve, link, AI_chk, status, cve_info_status, collect_time(64).

### CVE_Info
공식 CVE 상세.

| 컬럼군 | 컬럼 |
|---|---|
| 키 | id PK, CVE_Code VARCHAR(50) UNIQUE |
| 시간/상태 | collect_time, state, dateReserved, datePublished, dateUpdated |
| 대상/설명 | product, descriptions, effect_version |
| 분류 | cweId, Attak_Type |
| CVSS | CVSS_Score, CVSS_Vertor, CVSS_Serverity, CVSS_vertorString |
| 대응/원본 | solutions, Response_data LONGTEXT |

인덱스: CVE_Code, CVSS_Serverity, collect_time(64), datePublished(20).

### CVE_Packet_AI_Analysis
PoC 단계별 AI 분석.

| 컬럼군 | 컬럼 |
|---|---|
| 키/연결 | id PK, link, download_path |
| 분석 | cve_summary, step, packet_text |
| 단계 | vuln_stage, stage_description |
| MITRE | mitre_tactic, mitre_technique |
| 탐지/대응 | snort_rule, remediation, expected_response |
| 영향제품 | affected_products JSON |

인덱스: link, step.

### CVE_Integrated_Data
PoC·CVE·AI 통합 데이터.
- 키: `id`, `hash_key VARCHAR(64) UNIQUE`
- PoC: `github_*`
- CVE: `cve_*`
- AI: `ai_*`
- 생성시각: `created_at`
- 인덱스: hash_key, cve_code, github_link

## 2. 사용자·협업 테이블

### users
| 컬럼 | 형식/제약 | 설명 |
|---|---|---|
| id | INT PK AI | 사용자 ID |
| username | VARCHAR(50) UNIQUE NOT NULL | 로그인 ID |
| password | VARCHAR(255) NOT NULL | bcrypt 해시 |
| name/nickname | VARCHAR | 이름·닉네임 |
| email | VARCHAR(100) NOT NULL | 이메일, 현행 평문 |
| phone | VARCHAR(20) | 전화번호, 현행 평문 |
| role | ENUM(user,analyst,admin) | 권한 |
| created_at/last_login | TIMESTAMP | 생성·최근 로그인 |

현행에는 잠금·실패횟수·비밀번호변경일·최초변경 플래그가 없다.

### board_posts
`id`, `user_id FK`, `title`, `content`, `file_path`, `views`, `created_at`, `updated_at`.

### poc_ratings
`id`, `poc_id`, `user_id FK`, `rating(1/-1)`, 생성·수정시각. `(user_id,poc_id)` UNIQUE.

### poc_comments
`id`, `poc_id`, `user_id FK`, `content`, 생성·수정시각.

### poc_reanalyze_history
`id`, `poc_id`, `user_id FK NULL`, `created_at`.

### chat_messages
`id`, `user_id FK`, `username`, `nickname`, `message`, `created_at`. 런타임 코드에서 이미지 관련 컬럼이 추가될 수 있다.

## 3. API·AI 계정 테이블

### api_tokens
`id`, `token VARCHAR(64) UNIQUE`, `name`, `created_by`, `created_at`, `last_used_at`, `expires_at`, `is_active`, `permissions JSON 문자열`.

보안 주의: token은 현행 평문 저장이며 관리자 조회 API가 전체 토큰을 반환한다.

### AI_Quota_Management
`id`, `account_email UNIQUE`, `daily_analysis_count`, `quota_exhausted_count`, `last_429_error_time`, `is_active`, 생성·수정시각.

### gemini_accounts
`id`, `account_name UNIQUE`, `account_email`, `folder_path`, `is_active`, `display_order`, `created_at`.

### gemini_quota_usage
`id`, `account_id FK`, `usage_date`, 요청·성공·실패 수, 초과시각·상태, 최근사용·생성·수정시각. `(account_id,usage_date)` UNIQUE.

### gemini_quota_events
`id`, `account_id FK`, `event_type`, `cve_code`, `poc_link`, `error_message`, `created_at`.
event_type: success, failed, quota_exceeded, rate_limit, account_switched.

## 4. 대시보드 집계 테이블
| 테이블 | 키/주요 필드 | 용도 |
|---|---|---|
| dashboard_stats_daily | stat_date UNIQUE, total_cves/pocs, analyzed/pending, updated_at | 일별 전체 통계 |
| dashboard_cvss_distribution | stat_date+severity UNIQUE, count | 심각도 분포 |
| dashboard_product_stats | stat_date+product UNIQUE, count, rank_order | 제품 Top N |
| dashboard_cwe_stats | stat_date+cwe_id UNIQUE, count, rank_order | CWE Top N |
| dashboard_attack_type_stats | stat_date+attack_type UNIQUE, count, rank_order | 공격유형 Top N |
| dashboard_attack_stage_stats | stat_date+vuln_stage UNIQUE, count, rank_order | 공격단계 Top N |
| dashboard_recent_cves | stat_date, cve_code, product, collect_time, CVSS, state, rank | 최근 수집 CVE |
| dashboard_latest_cves | stat_date, cve_code, product, datePublished, CVSS, state, rank | 최신 게시 CVE |
| dashboard_recent_pocs | stat_date, poc_id, title, writer, cve, collect_time, 상태, link, rank | 최근 PoC |

모든 집계 테이블은 `stat_date` 및 필요한 `rank_order` 인덱스를 사용한다.

## 5. 런타임 메모리 데이터
회원가입·비밀번호 재설정 인증코드는 DB 테이블이 아니라 Node 프로세스 메모리 Map/Object에 3분 유효로 저장된다. 서버 재시작 시 소멸하며 다중 인스턴스 공유가 불가능하다.

## 6. 관계 요약
```text
users ─┬─ board_posts
       ├─ poc_ratings
       ├─ poc_comments
       ├─ poc_reanalyze_history
       └─ chat_messages

gemini_accounts ─┬─ gemini_quota_usage
                 └─ gemini_quota_events

Github_CVE_Info + CVE_Info + CVE_Packet_AI_Analysis
                 └─> CVE_Integrated_Data
                 └─> dashboard_*
```

## 7. 운영 검증 SQL
```sql
SELECT TABLE_NAME
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'TOTORO'
ORDER BY TABLE_NAME;

SELECT TABLE_NAME, COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_KEY
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'TOTORO'
ORDER BY TABLE_NAME, ORDINAL_POSITION;
```
