# 1.1 백업·복구 및 변경관리

## 문서 정보
- 기준일/버전: 2026-07-21 / 1.0
- 현행 판정: 기존 문서에는 백업 예시가 있으나 실제 CVE_BOT 전용 백업 작업 스케줄은 확인되지 않음

## 1. 백업 대상
| 대상 | 내용 | 비밀정보 주의 |
|---|---|---|
| MySQL | `TOTORO` 전체 스키마·데이터 | 덤프 암호화·접근통제 |
| CVE 파일 | `C:\aiserver\CVE_BOT\CVE` | 악성 PoC 가능, 격리 보관 |
| 소스 | Git 추적 파일 | 미커밋 변경 별도 확인 |
| 설정 | config 계열, AI 설정, 환경변수 | 토큰·DB 비밀번호 포함 가능 |
| 인증서 | Caddy 데이터, server.cert/key | 개인키 최고등급 보호 |
| 로그 | 앱·PM2·Caddy·Windows 이벤트 | 개인정보·인증정보 포함 가능 |
| 운영 문서 | `SecurityReview` 및 승인 문서 | 연락처 접근통제 |

## 2. 권장 백업 정책
조직의 공식 정책이 확정되기 전 적용할 기준안이다.

| 대상 | 주기 | 보관 | 저장 위치 |
|---|---|---|---|
| DB 전체 | 매일 | 일 30일, 월 12개월 | 별도 암호화 저장소 |
| 설정/문서 | 변경 시 | 버전별 | Git + 승인 저장소 |
| CVE 파일 | 매일 증분/주 1회 전체 | 업무정책 기준 | 악성코드 취급 가능한 저장소 |
| 감사로그 | 실시간/일 단위 | 접속 1~2년, 권한 5년 | 중앙 로그/SIEM |
| 인증서/키 | 변경 시 | 현행+직전 | 제한된 시크릿 저장소 |

## 3. DB 백업 예시
비밀번호를 명령행에 직접 넣지 않는다.

```powershell
mysqldump -h localhost -P 7002 -u <backup-user> -p `
  --single-transaction --routines --triggers TOTORO `
  > <승인된백업경로>\TOTORO_YYYYMMDD_HHMMSS.sql
```

백업 후 확인:
- 명령 종료코드
- 파일 크기와 생성시각
- 암호화 여부
- 해시값
- 별도 서버 복사 결과
- 복구시험 상태

## 4. 복구 절차
1. 장애 범위와 복구시점 승인
2. 원본 보존 및 쓰기 작업 중지
3. 대상 DB·파일의 별도 스냅샷
4. 격리된 검증 환경에서 백업 무결성 확인
5. 스키마 버전과 애플리케이션 버전 일치 확인
6. 승인된 계정으로 복구
7. 테이블 건수·참조·주요 기능 검증
8. 웹·수집·AI 순차 재개
9. 결과 기록

DB 복원 예시:
```powershell
mysql -h localhost -P 7002 -u <restore-user> -p TOTORO `
  < <승인된백업파일>
```

## 5. 복구 검증
- users, CVE_Info, Github_CVE_Info 등 핵심 테이블 조회
- 최신 CVE·PoC·AI 데이터 기준시각 확인
- 로그인·대시보드·CVE 상세·관리자 기능
- API 토큰 상태와 만료일
- 대시보드 통계 재집계
- 로그 오류 없음

## 6. 현행 미비점
- 전용 자동 백업 작업 미확인
- 복구시험 이력 미확인
- 로그 장기보존·중앙전송 미확인
- DB가 0.0.0.0:7002에 바인딩
- 설정 파일에 평문 비밀정보 존재

## 7. 변경관리 절차
1. 변경요청: 목적·대상·영향·위험·롤백 작성
2. 검토: 담당 개발자·운영자·보안·DB/네트워크
3. 승인: 서비스 책임자
4. 사전백업 및 점검
5. 시험환경 검증
6. 운영 반영
7. 기능·로그·성능·보안 검증
8. 문서와 변경관리대장 개정
9. 결과 통보

## 8. 롤백 기준
- 주요 API·로그인·DB 오류
- 데이터 정합성 훼손
- 처리시간 또는 오류율 급증
- 승인되지 않은 포트·권한·외부 연결 발생
- 보안 통제 우회
