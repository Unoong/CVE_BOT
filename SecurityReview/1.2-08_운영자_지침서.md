# 1.2 운영자 지침서

## 문서 정보
- 기준일/버전: 2026-07-21 / 1.0
- 대상: 시스템·애플리케이션·DB·보안 운영자

## 1. 운영자 책임
- 서비스 가용성·데이터 정합성·보안 통제 유지
- 일일·주간·월간 점검
- 계정·역할·API 토큰 최소권한 관리
- 수집·AI 분석·대시보드 집계 상태 관리
- 백업·복구·변경·장애 기록
- 비밀정보와 개인정보 보호

## 2. 운영 시작 점검
```powershell
Get-Service MySQL80,W32Time
w32tm /query /status
Set-Location C:\aiserver\CVE_BOT\web
pm2 status
Get-ScheduledTaskInfo -TaskName CVE_BOT_Dashboard_Init
```

프로젝트 Python 확인:
```powershell
Get-CimInstance Win32_Process |
  Where-Object CommandLine -match 'CVE_BOT|run_ai_analysis|collector' |
  Select-Object ProcessId,CreationDate,CommandLine
```

## 3. 사용자·권한 운영
- 신규 가입 기본 역할을 확인한다.
- analyst/admin 부여는 업무와 승인 근거를 확인한다.
- 퇴직·이동·업무종료 시 즉시 역할 회수 또는 삭제한다.
- 본인 관리자 계정 외 공용 admin 사용을 금지한다.
- 변경 전·후 사용자, 역할, 승인자, 시각을 감사기록에 남긴다.

현행 앱은 권한 변경 전용 감사테이블이 없으므로 외부 변경관리 기록이 필요하다.

## 4. API 토큰
- 토큰 이름에 시스템·목적·담당자를 명시한다.
- 최소 권한과 만료일을 부여한다.
- 생성 시 한 번만 전달하고 안전한 시크릿 저장소에 보관한다.
- URL 쿼리 토큰보다 헤더를 사용한다.
- 사용 종료·유출 의심 시 즉시 비활성화·폐기한다.
- 현행 DB는 토큰을 평문 저장하므로 접근권한을 엄격히 제한한다.

## 5. 수집 운영
- GitHub/CIRCL/CVE API 응답과 제한 확인
- 중복 적재·수집 지연·미처리 상태 확인
- 외부 API 토큰을 로그에 출력하지 않음
- PoC 파일은 악성코드로 간주하고 실행하지 않음

## 6. AI 분석 운영
- `run_ai_analysis.py`가 의도한 단일 프로세스인지 확인
- `AI_chk=N` 대기량, 최근 성공, 쿨다운, quota 이벤트 확인
- CLI 오류 시 실제 로그 명령과 현재 코드 비교
- 계정 인증 폴더를 임의 교체하지 않음
- 실패 반복 시 무제한 재시작하지 않음

## 7. DB 운영
- 애플리케이션용 최소권한 DB 계정 사용 권장
- 현행 root 사용·7002 전역 바인딩은 개선 대상
- 스키마 변경 전 백업·영향분석·롤백 준비
- `migration_package` SQL은 번호 순서와 적용 여부를 확인
- 014/015 인덱스는 중복 적용 오류에 주의

## 8. 웹 운영
- PM2 상태와 backend/frontend/caddy 로그 확인
- Caddy 인증서 갱신·DNS·80/3000 접근 확인
- 3001·32577·32578은 Caddy 내부 원본으로 제한 권장
- debug 로그는 인증코드 등 민감정보 노출 위험이 있어 운영 사용을 최소화

## 9. 로그 운영
- 애플리케이션 운영 로그와 보안 감사로그를 구분
- 로그인: ID·IP·시각·성공여부
- 업무: 사용자·IP·메뉴/API·대상·행위·결과
- 권한: 부여·변경·삭제 전후값·승인자
- 중앙 로그 전송과 1·2·5년 보존정책 적용
- 로그 삭제/flush는 승인과 백업 없이 수행하지 않음

## 10. 보안 운영
- RDP·WinRM·SMB·MySQL 접근을 관리망/IP로 제한
- Defender 제외 경로 승인 여부와 대체통제 확인
- V3·SecuMS·QueryOne 설치·콘솔 연계
- 하드코딩 DB/메일/JWT/API 토큰 폐기·외부화
- Windows Administrator 개인별 계정 전환
- 비밀번호·잠금·유휴 세션·멀티로그인 통제 개선

## 11. 배포·변경

2. 코드 리뷰·시험

4. 승인된 시간에 반영

6. 포트·로그·기능 검증
7. Git 커밋·원격 반영
8. 관련 문서·변경관리대장 갱신

## 12. 운영 종료
- 미해결 장애·쿨다운·변경사항을 다음 운영자에게 인계
- 비밀정보가 콘솔·클립보드·임시파일에 남지 않았는지 확인
- 개인 계정 로그아웃
- 운영일지 저장
