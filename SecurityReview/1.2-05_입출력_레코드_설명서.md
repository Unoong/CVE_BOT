# 1.2 입·출력 레코드 설명서

## 문서 정보
- 기준일/버전: 2026-07-21 / 1.0
- 민감값 표기: 토큰·비밀번호·개인키는 구조만 설명하고 값을 기재하지 않음

## 1. GitHub PoC 수집
### 입력
| 필드 | 형식 | 설명 |
|---|---|---|
| 검색어 | 문자열 | `CVE-YYYY-NNNN` 등 |
| API 토큰 | 비밀 문자열 | GitHub 인증 |
| 수집 한도 | 정수 | 기본/특정 CVE별 한도 |
| API 응답 | JSON | 저장소, 작성자, 날짜, README 등 |

### 출력
`Github_CVE_Info`:
`date`, `collect_time`, `link`, `title`, `writer`, `cve`, `readme`, `download_path`, `status`, `trans_msg`, `AI_chk`, `cve_info_status`

## 2. CIRCL/CVE 상세 수집
### 입력
- CIRCL `/last` 또는 CVE 단건 API JSON
- CVE 코드

### 출력
`CVE_Info`:
`CVE_Code`, `state`, 예약/게시/갱신일, `product`, `descriptions`, 영향버전, CWE, 공격유형, CVSS 점수·벡터·심각도, 해결방안, 원본 응답

## 3. AI 분석
### 입력 레코드
| 필드 | 출처 | 설명 |
|---|---|---|
| link | Github_CVE_Info | PoC 식별 |
| download_path | Github_CVE_Info | 로컬 PoC 경로 |
| cve/readme | Github_CVE_Info | 분석 문맥 |
| prompt | prompt 파일 | 분석 지시 |
| 설정 | ai_analysis_config.json | 제한·재시도·크기 |

### CLI 입력
- 프롬프트 파일을 stdin 리다이렉트로 전달
- PoC 경로는 add-dir 형태로 전달
- 비밀값이나 계정 인증 파일은 프롬프트에 포함하지 않음

### 출력 레코드
`CVE_Packet_AI_Analysis`:
`link`, `download_path`, `cve_summary`, `step`, `packet_text`, `vuln_stage`, `stage_description`, `mitre_tactic`, `mitre_technique`, `snort_rule`, `remediation`, `expected_response`, `affected_products`

## 4. 통합 데이터
### 입력
- Github_CVE_Info
- CVE_Info
- CVE_Packet_AI_Analysis

### 출력
- `hash_key`: 통합행 고유값
- `github_*`, `cve_*`, `ai_*`
- `created_at`

## 5. 사용자 인증
### 회원가입 입력(JSON)
```json
{
  "username": "string",
  "password": "<secret>",
  "name": "string",
  "nickname": "string?",
  "email": "string",
  "phone": "string",
  "code": "<verification-code>"
}
```

### 로그인 입력(JSON)
```json
{ "username": "string", "password": "<secret>" }
```

### 로그인 출력(JSON)
```json
{
  "token": "<JWT>",
  "user": {
    "id": 0,
    "username": "string",
    "name": "string",
    "nickname": "string",
    "email": "string",
    "phone": "string",
    "role": "user|analyst|admin"
  }
}
```

## 6. CVE 목록 출력
```json
{
  "cves": [],
  "total": 0,
  "page": 1,
  "limit": 20
}
```
주요 행 필드: CVE 코드, 상태, 제품, CVSS 점수/심각도, 수집·게시일, PoC·AI 개수.

## 7. DB 조회
### 입력(JSON)
```json
{
  "table": "Github_CVE_Info|CVE_Info|CVE_Packet_AI_Analysis",
  "page": 1,
  "limit": 20,
  "searchField": "허용 필드",
  "searchValue": "string"
}
```

### 출력
```json
{ "rows": [], "total": 0, "page": 1, "limit": 20 }
```

## 8. 외부 Export
### 인증
`X-API-Token: <secret>` 사용을 원칙으로 하며 URL 쿼리 토큰은 로그 노출 가능성이 있어 사용하지 않는 것이 좋다.

### 목록 출력
```json
{
  "success": true,
  "pagination": { "page": 1, "limit": 20, "total": 0 },
  "data": []
}
```

### 전송확인 입력
```json
{ "links": ["https://..."] }
```

### 출력
```json
{ "success": true, "updated_count": 0 }
```

## 9. 로그 레코드
Python 기본 형식:
```text
YYYY-MM-DD HH:MM:SS - CVE_BOT - LEVEL - message
```

웹 형식:
```text
[KST locale timestamp] [LEVEL] message
```

로그에 비밀번호·JWT·API 토큰·인증코드를 기록하지 않아야 하나, 현행 debug 코드에는 이메일 인증코드 출력이 있어 개선 관리 대상이다.

## 10. 파일 입출력
| 유형 | 입력 | 출력 |
|---|---|---|
| PoC | GitHub 저장소/ZIP | `CVE\CVE-...\순번\...` |
| 업로드 이미지 | multipart `file`, 이미지 MIME, 최대 10MB | `web\uploads\...`, imageUrl |
| 설정 | JSON | 런타임 옵션 |
| MITRE | `mitre_attack_matrix.csv` | 기법/전술 JSON |
| 로그 | 프로그램 이벤트 | `logs\` 파일 |
