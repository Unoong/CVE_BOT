# 1.1 장애조치 매뉴얼

## 문서 정보
- 기준일/버전: 2026-07-21 / 1.0
- 원칙: 관찰 → 영향판단 → 증거보존 → 승인 → 조치 → 검증 → 기록

## 1. 공통 초동조치
1. 발생 시각, 신고자, 증상, 영향 사용자를 기록한다.
2. 무조건 재부팅하거나 로그를 삭제하지 않는다.
3. PM2·Python·MySQL 상태, PID, LISTEN 포트, 최근 오류를 확보한다.
4. 보안사고 가능성이 있으면 격리·증거보존을 우선하고 정보보호 담당자에게 즉시 통보한다.
5. 승인된 최소 조치만 수행한다.

## 2. 웹 접속 불가
### 확인
```powershell
Get-NetTCPConnection -State Listen |
  Where-Object LocalPort -in 80,3000,3001,32577,32578
Set-Location C:\aiserver\CVE_BOT\web
pm2 status
pm2 logs caddy --lines 100
pm2 logs cve-backend --lines 100
pm2 logs cve-frontend --lines 100
```

### 조치
- 한 프로세스만 비정상이면 해당 PM2 앱만 재시작한다.
- 인증서/ACME 오류는 Caddy 로그와 DNS·80 포트 정책을 확인한다.
- DB 오류가 원인이면 웹 반복 재시작보다 DB 장애 절차를 따른다.

## 3. API 500·로그인 실패
- backend-error 로그 확인
- MySQL80 상태와 DB 연결 확인
- JWT 시크릿·DB 설정 파일 변경 이력 확인(값 출력 금지)
- 서버 시간 편차 확인
- 특정 계정만 실패하면 계정 상태와 비밀번호 만료 정책 확인

현행 앱에는 5회 실패 잠금이 없으므로 반복 실패가 보이면 공격 가능성을 검토한다.

## 4. DB 연결 실패·성능 저하
```powershell
Get-Service MySQL80
Get-NetTCPConnection -LocalPort 7002 -State Listen
```

- 디스크 여유와 MySQL 오류 로그 확인
- 장기 실행 쿼리·연결 수 확인
- 승인 없이 프로세스 강제 종료, 인덱스 변경, DB 재시작 금지
- 재시작이 필요하면 웹·Python 쓰기 작업을 먼저 중지

## 5. Python 수집 중단
- 관련 PID와 시작시각 확인
- 최근 `cve_bot.log`, 수집기별 로그 확인
- 외부 API 응답, 토큰 제한, 네트워크/DNS 확인
- 중복 프로세스가 없는 상태에서 해당 수집기만 재시작

## 6. AI 분석 중단·구방식 실행
- PID와 생성시각, 명령줄을 확인한다.
- Python은 시작 시 코드를 메모리에 적재하므로 파일 수정만으로 기존 프로세스가 바뀌지 않는다.
- 로그의 실제 CLI 명령과 `ai_analyzer.py` 현행 템플릿을 비교한다.
- 연속 실패 쿨다운 파일(`logs\analysis_cooldown.json`)과 재개시각을 확인한다.
- 쿨다운 삭제는 원인 해소와 승인 후 수행한다.
- 구코드를 메모리에 가진 프로세스는 정상 종료 후 현행 코드로 재시작한다.

## 7. Gemini/Antigravity 할당량·인증 오류
- `gemini_quota_usage`, `gemini_quota_events`와 AI 로그 확인
- 활성 계정과 승인된 고정 계정 정책 확인
- 429/quota 오류는 무리한 반복 재시도 금지
- 인증 폴더를 임의 삭제·교체하지 말고 계정 담당자 승인

## 8. 대시보드 통계 불일치
- `CVE_BOT_Dashboard_Init` 최근 실행 결과 확인
- `logs`의 집계 배치 로그 확인
- 수동 집계 전 DB 부하와 동시 실행 여부 확인
- 원본 테이블 수치와 `dashboard_*` 기준일 비교

## 9. 인증서·TLS 장애
- Caddy 로그, DNS, 시스템 시각, 인증서 만료 확인
- Let's Encrypt HTTP-01 사용 시 80 포트 도달성 확인
- 자체서명 인증서로 임의 전환하지 않는다.
- HTTP로 우회 개방하지 않는다.

## 10. 보안사고 의심
대상:
- 비정상 RDP/WinRM/MySQL 접속
- 관리자·API 토큰 탈취
- 악성 PoC 실행 또는 Defender 탐지
- 비밀정보 저장소 노출
- 로그 삭제·변조

조치:
1. 정보보호 담당자 즉시 통보
2. 관련 로그·프로세스·네트워크 연결·파일 해시 확보
3. 승인된 방식으로 네트워크 격리
4. 자격정보 폐기·교체
5. 원인 제거 후 복구 및 재발방지

Defender가 `C:\aiserver`를 제외하고 있으므로 이 경로의 악성 파일은 탐지되지 않을 수 있다.

## 11. 장애 종료 조건
- 기능·데이터·보안 상태 정상 확인
- 임시조치 제거 또는 추적 항목 등록
- 사용자·관계자 종료 통보
- 원인, 영향, 타임라인, 조치, 재발방지 문서화
